# Design: m1-link-loss-freshness

Architect: `gemini (gemini-4-carbon, medium)`

## Context
- `internal/mavlink/config.go:27-85,178-189`: `Config` validates `skg_hz` (`1..5`, default `1 Hz`) with `DisallowUnknownFields()`; no link-loss timeout setting exists yet.
- `internal/mavlink/component.go:105-116,209-222,256-310`: `start` runs 3 goroutines (`readLoop`, `tickLoop`, `publisher.Run`). `tickLoop` (`294-310`) ticks at `skgInterval` (`200 ms..1 s`), calling `tracker.BuildPeriodicBatch()` and `publisher.EnqueuePeriodic(batch)` without evaluating silent sessions or publishing tick-driven Lane 3 events.
- `internal/mavlink/tracker.go:33-37,70-128,201-309,569-618,691-762`: `vehicleSession` (`109-118`) tracks `snap`, `rev`, `has*` flags, and `peerAddr` without link-loss state. `applyStatusText` (`569-618`) increments `sess.rev++` and sets `UrgentSKGSync: true` (`616`), rewriting all 22 triples even though `#253 STATUSTEXT` is absent from `VehicleSnapshot` (`internal/uxsvocab/snapshot.go:53-97`).
- `internal/mavlink/publisher.go:10-215`: `Publisher` buffers pre-marshaled periodic slices in `periodicCh` (`PeriodicQueueCap = 2`) and uses `maxAttemptedRev` (`35,182-202`), `lastConfirmedRev` (`36,185,209-213`), and `skipEqualSysIDs` (`175-187`) so queued periodic batches cannot overwrite newer urgent flushes. `git log -S 'EnqueuePeriodic'` + `git grep` confirm `PeriodicQueueCap`, `EnqueuePeriodic`, `DroppedPeriodic`, and `maxAttemptedRev` have zero callers outside `internal/mavlink/{component.go,publisher.go,mavlink_test.go}`.
- `internal/uxsvocab/snapshot.go:48-53,385-410` & `openspec/specs/mavlink-ingest/spec.md:7-28,55-72`: `uxs.vehicle.v1` emits a locked constant 22-predicate `signal` set; Lane 3 currently requires an SKG flush on `#253 STATUSTEXT`.
- `docs/architecture/comms-topology.md:68-71`: `sitl-local` / `direct-bench` (`20–50 Hz`) and `mesh-high-rate` (`10–30 Hz`) run `1 Hz` heartbeats, whereas `mesh-supervisory` (US915 LoRa) sends `0.2–1 Hz` state deltas (`1–5 s` normal inter-packet gap).
- `ui/src/lib/stores/telemetry.svelte.ts:39-46` already accepts `link_lost` / `link_restored` on `bbops.telemetry.events.<sysid>`. `ui/src/lib/stores/skg.svelte.ts:608-629` and `ui/src/lib/hud/view-model.ts:443-474` derive freshness from `Triple.Timestamp` (`observedAt` / `poseObservedAt`) and `WS #2` receipt time (`ingestedAtMs`).

## Goals / Non-Goals
- **Goals:** Detect per-`sysid` silence on the existing SKG tick using injected `time.Time` in `Tracker`; emit one `link_lost` edge after crossing threshold and `link_restored` on the next accepted packet; build periodic SKG batches at flush time with urgent-first priority and non-blocking UDP reads; stop `#253 STATUSTEXT` SKG flushes while keeping its `bbops.telemetry.events.<sysid>` event.
- **Non-Goals:** New goroutines or per-`sysid` `time.Timer`s; evicting silent vehicles from `ENTITY_STATES`; UI stale-health rendering (`#39`); outbound `#76`/`#84` C2 (`#11`).

## Decisions

### D1: Per-`sysid` silence threshold configuration & `LinkTier` scaling (`#27`)
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (`LinkTier`-scaled configurable timeout)** — Optional `link_timeout_ms` (default `3000`, `3×` `1 Hz` heartbeat) for `sitl-local` / `direct-bench` / `mesh-high-rate`, plus `supervisory_timeout_ms` (default `10000`, `2×` `0.2 Hz` LoRa interval) when `sess.snap.LinkTier == "mesh-supervisory"`, evaluated in `Tracker.EvaluateSilence(now)` on `tickLoop`. | ~35 LOC in `internal/mavlink/{config.go,tracker.go}` | `internal/mavlink` (`Config` gains optional fields; `configs/bbops.json` valid unchanged) | False `link_lost`/`link_restored` flapping on `0.2–1 Hz` LoRa supervisory links without slowing `3 s` bench/teleop loss detection |
| **Option B (Single flat configurable `link_timeout_ms`, default `3000`)** — One uniform silence timeout across all four `LinkTier` values on `tickLoop`. | ~20 LOC in `internal/mavlink/{config.go,tracker.go}` | `internal/mavlink` | Co-hosting `3 s` `direct-bench` and `0.2 Hz` `mesh-supervisory` peers in one `mavlink-udp` instance without false LoRa loss edges |

**Adopter seam:** Callers omitting timeout fields in `configs/bbops.json` get `3000 ms` bench/high-rate detection automatically (`skgInterval` quantization adds at most `1 / skg_hz`, i.e. `<= 1 s` at default `1 Hz`). `#39` (`ui/src/lib/hud/view-model.ts`) must align its stale-vehicle cutoff with the chosen timeout contract rather than hardcoding a tighter bound.

### D2: SKG representation of per-`sysid` link loss & constant-predicate invariant (`#27`)
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (Keep locked 22-predicate `uxs.vehicle.v1`; freeze SKG timestamps on silence + emit Lane 3 edges)** — On `link_lost`, `Tracker` sets `sess.linkLost = true` and emits `TransitionEvent{Kind: "link_lost"}` on `bbops.telemetry.events.<sysid>` without mutating `VehicleSnapshot` or advancing `ObservedAt` (halting periodic re-upserts via `D3` so `ENTITY_STATES` retains last-known faults and true last-packet `Triple.Timestamp`). On packet resume, `Tracker` clears `linkLost`, emits `link_restored`, and triggers an urgent SKG flush with fresh `ObservedAt`. | ~30 LOC in `internal/mavlink/{tracker.go,component.go}`; `0` LOC in `uxsvocab` / `ui/` | `internal/mavlink` only (all `22`/`23`-predicate `uxsvocab` & host tests untouched) | Filtering `uxs.link.online == false` directly via GraphQL `entitiesByPredicate` without comparing `Triple.Timestamp` (`observedAt`) against wall clock |
| **Option B (Add 19th `uxs.*` predicate `uxs.link.online` [`bool`], 23 constant producer triples)** — Every `VehicleSnapshot` emits `uxs.link.online` (`true` while live, `false` + urgent SKG flush on `link_lost`), decoupling `LinkObservedAt` from `ObservedAt` so `link_lost` does not overwrite vehicle telemetry timestamps in `skg.svelte.ts:621-622`. | ~110 LOC across `internal/uxsvocab`, `internal/mavlink`, `internal/host`, `ui/src/lib/stores/skg.svelte.ts` | `openspec/specs/mavlink-ingest/spec.md` (`18->19` / `22->23` requirements), `uxsvocab`, `mavlink`, `host`, `ui` | Keeping `#27 + #29` scoped strictly to `internal/mavlink` with zero `uxsvocab` or UI store churn |

**Adopter seam:** Under **Option A**, doing nothing in `uxsvocab` / `skg.svelte.ts` preserves every existing 22-predicate consumer; `#39` determines staleness from frozen `vehicle.observedAt` (`Triple.Timestamp`) plus live `WS #1` `link_lost`/`link_restored` events (note: a single UDP datagram produces at most one `IngestOutcome.Event`, so if a resuming packet also flips `HEARTBEAT`/`SYS_STATUS`, `link_restored` must either fold those reasons into `Reasons` or return `Events []TransitionEvent`). Under **Option B**, `skg.svelte.ts` must ignore `uxs.link.online`'s timestamp when computing `vehicle.observedAt`, or `link_lost` upserts would masquerade as fresh vehicle telemetry.

### D3: Build-at-flush periodic SKG worker & `#253 STATUSTEXT` flush removal (`#29`)
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (Coalesced `periodicPending` + `lastConfirmedRev[sysid]` filter at flush time; `#253` event-only)** — Replace `periodicCh` with `NotifyPeriodic()` (`periodicPending` flag + wake signal). `publisher.Run` drains `urgentSysIDs` strictly ahead of `periodicPending`, calls `Tracker` at flush time to marshal only sessions with `rev > lastConfirmedRev[sysid]`, advances `lastConfirmedRev` on `PublishBatchToStream` ack, removes `PeriodicQueueCap`/`EnqueuePeriodic`/`DroppedPeriodic`/`maxAttemptedRev`, and drops `UrgentSKGSync` + `sess.rev++` on `#253 STATUSTEXT` (updating `lastPacketAt` only). | Net ~`-55` LOC in `internal/mavlink/{publisher.go,tracker.go,component.go}` | `internal/mavlink` + `openspec/specs/mavlink-ingest/spec.md` | Reading `DroppedPeriodic()` count or expecting `1 Hz` duplicate `ENTITY_STATES` `kvRevision` bumps when zero telemetry frames arrive |
| **Option B (Build-at-flush periodic worker WITHOUT `lastConfirmedRev` suppression; `#253` event-only)** — Build periodic batches at flush time for all non-`linkLost` sessions on every tick regardless of whether `sess.rev` changed since the prior flush, skipping only after `link_lost` fires. | Net ~`-65` LOC in `internal/mavlink` | `internal/mavlink` + `ENTITY_STATES` KV / `WS #2` | Stopping redundant JetStream `ENTITY` writes and `WS #2` `ingestedAtMs` refreshes (`view-model.ts:453-474`) during the `0..link_timeout_ms` quiet window |

**Adopter seam:** `Publisher` is internal to `internal/mavlink`; `host.Runtime` and `configs/bbops.json` require no changes. Under **Option A**, callers watching `WS #2` receive `put` frames when vehicle state or telemetry timestamps change (`#0,#1,#31,#32,#33`), and zero duplicate `put`s while a vehicle is silent; transient `PublishBatchToStream` errors leave `lastConfirmedRev` unadvanced so the next tick retries automatically.

## Risks / Trade-offs
- **Tick quantization (`1 / skg_hz`):** Evaluating silence on `tickLoop` avoids per-`sysid` timers at the cost of `0..skgInterval` (`<= 1 s` at `1 Hz`, `<= 250 ms` at `4 Hz`) detection jitter; unit tests exercise `Tracker.EvaluateSilence(now)` directly at exact boundaries.
- **Resuming packet with concurrent state edge:** A packet ending link loss may simultaneously flip `ControlAuthority` or increment `failsafes`; `IngestOutcome` (`tracker.go:100-107`) must not silently drop either `link_restored` or the state-edge reason/urgent SKG sync.
- **`#253`-only keepalive:** An accepted `#253 STATUSTEXT` proves link liveness (`lastPacketAt = now` and `link_restored` if previously lost); under `D3 Option A`, if previously lost and `D2 Option A/B` flushes on restoration, `link_restored` still triggers an urgent SKG sync while steady-state `#253` skips SKG flushes.

## Migration Plan
1. Apply owner rulings on `OQ1`–`OQ3` (updating `specs/mavlink-ingest/spec.md` if `OQ2` selects Option B's 23rd predicate).
2. Implement in `internal/mavlink` (and `uxsvocab`/`ui` only if `OQ2 = Option B`) in one atomic PR before `#39` and `#11`, updating `mavlink_test.go` (`DroppedPeriodic` / `#253 UrgentSKGSync` assertions + link-loss history model). Rollback is a single PR revert.

## Open Questions
1. **`OQ1` (`D1` — Silence threshold & `LinkTier` scaling) (**Needs owner ruling**):** Should `internal/mavlink` use **Option A** (`LinkTier`-scaled `link_timeout_ms = 3000` default + `supervisory_timeout_ms = 10000` for `mesh-supervisory`) or **Option B** (single flat `link_timeout_ms = 3000` across all `LinkTier`s)?
2. **`OQ2` (`D2` — SKG link-loss representation) (**Needs owner ruling**):** Should link loss follow **Option A** (keep the locked 22-predicate `uxs.vehicle.v1` unchanged, freeze SKG `Triple.Timestamp` / stop periodic re-upserts on silence, emit `link_lost`/`link_restored` on `bbops.telemetry.events.<sysid>`, and flush SKG on `link_restored`) or **Option B** (add a 23rd constant predicate `uxs.link.online` [`bool`] across `uxsvocab`, `openspec/specs/mavlink-ingest/spec.md`, and `skg.svelte.ts`)?
3. **`OQ3` (`D3` — Build-at-flush periodic SKG worker & `#253 STATUSTEXT`) (**Needs owner ruling**):** Confirm **Option A** (coalesced `NotifyPeriodic` + `lastConfirmedRev[sysid]` filter at flush time so unchanged/silent sessions stop re-upserting, plus event-only `#253 STATUSTEXT`) vs **Option B** (re-upsert all non-lost sessions every tick without `lastConfirmedRev` filtering)?
