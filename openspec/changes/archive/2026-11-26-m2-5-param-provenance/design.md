## Goals / Non-Goals
- **Goals:** Make baseline provenance (`"domain-default"` vs. `"vehicle-reported"` fixtures) and local-only draft status unmistakable before and after editing; expose per-parameter baseline, draft, units, and `[min, max]`/`step` bounds plus a compact target-vehicle (`UXS #<sysid> · <domain>`) change summary; add exact numeric inputs alongside sliders with deterministic validation; explain unavailable vehicle application in plain nearby copy; preserve `#40` per-vehicle draft continuity and external-contact/poisoned/invalid restrictions; guarantee zero outbound parameter writes or actuation commands.
- **Non-Goals:** MAVLink `PARAM_REQUEST_LIST`/`PARAM_SET` transport, `reported -> draft -> pending -> confirmed/failed` state machines (`#11`), changing `BENCH_TUNING_SPECS` control laws, or `#42` compact layout work.

## Decisions

### D1: Exact numeric input validation alongside range sliders
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (Strict validation — reject invalid, out-of-bounds, and off-step numeric text without mutating `staged`)** — Add pure `validateTuningNumericInput(spec, rawText)` in `tuning-rack.ts` returning `{ ok: true, value }` only when `rawText.trim()` parses to a finite number within `[spec.min, spec.max]` aligned to `spec.step` (within `1e-9` float tolerance), else `{ ok: false, reason: "empty" \| "nan" \| "below-min" \| "above-max" \| "off-step", message }`. Pair each dial/slider in `BenchWorkspace.svelte` with `<input type="number" min={spec.min} max={spec.max} step={spec.step}>`; valid edits update `draftStore.stageParam` and sync the slider immediately, while invalid text keeps the prior `staged` value untouched, sets `aria-invalid="true"`, and renders the inline bounds/step error until fixed, reverted, or cleared with `Escape`. | ~`+95` LOC across `tuning-rack.ts`, `BenchWorkspace.svelte` | `tuning-rack.ts`, `BenchWorkspace.svelte`, `bench.test.ts`, E2E | Silently coercing a typo (e.g. `32` instead of `3.2`, or `12.3` on a `0.5` step) into `spec.max` or a quantized neighbor |
| **Option B (Clamp & snap on commit with inline adjustment notice)** — Keep draft text local while typing; on `change`/`blur`/`Enter`, reject empty/`NaN` back to current `staged` with an inline notice, and commit finite numbers via `clampTuningValue(spec, parsed)` while displaying an inline `"Adjusted <raw> -> <committed> (<min>–<max> <unit>, step <step>)"` badge whenever `committed !== parsed`. | ~`+85` LOC across same files | Same files | Preventing out-of-bounds typos from staging `spec.min`/`spec.max` before the operator notices the adjustment note |

**Adopter seam:** Range sliders continue using `clampTuningValue` so pointer/arrow drags remain smooth and step-aligned, while exact text validation lives in pure `tuning-rack.ts` helpers. Resetting per-input transient draft/error state on `selectedEntityId` switch or `Revert Draft` happens inside `BenchWorkspace.svelte` so `DiagnosticsDraftStore` never stores unparsable strings; callers of `DiagnosticsDraftStore` doing nothing keep strongly typed `Record<string, number>` drafts.

### D2: Offline actuation boundary (`onApplyTuning`) & baseline provenance model (`TuningBaselineSource`)
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (Remove `onApplyTuning` prop from `BenchWorkspace` & `WorkspaceShell` until `#11`; add `TuningBaselineSource`)** — Add `TuningBaselineSource = "domain-default" \| "vehicle-reported"` onto `VehicleTuningDraftRecord`, `VehicleTuningView`, and `DormantVehicleDraftView` (`readVehicle` / `stageParam` default to `"domain-default"` when using `defaultTuningBaseline`, and accept `{ baseline, source: "vehicle-reported" }` in test fixtures). Remove `onApplyTuning` from `BenchWorkspace.svelte` and `WorkspaceShell.svelte` props so no button or handler can trigger parameter writes or show `"Apply N Staged"` before `#11`, keeping an explicitly disabled `"Apply to Vehicle (Unavailable)"` control paired with plain-language nearby text explaining that vehicle parameter writes are not enabled in this version. | ~`+60` / `-25` LOC across `tuning-rack.ts`, `BenchWorkspace.svelte`, `WorkspaceShell.svelte`, tests | `tuning-rack.ts`, `BenchWorkspace.svelte`, `WorkspaceShell.svelte`, `bench.test.ts:183-226,1083-1485`, `workspaces.test.ts:2391-2614` | Calling a mock `onApplyTuning` callback through `BenchWorkspace` before `#11` designs `pending -> confirmed/failed` |
| **Option B (Retain optional `onApplyTuning` strictly gated on `baselineSource === "vehicle-reported"` fixtures)** — Add the same `TuningBaselineSource` model (`"domain-default"` in all live flows), keep optional `onApplyTuning` on `BenchWorkspace`/`WorkspaceShell` for component tests, unconditionally disable/refuse `handleApply` whenever `baselineSource === "domain-default"` or `!onApplyTuning` (`+page.svelte`), and render plain-language unavailable-apply text whenever disabled without labeling any click `"Applied"`/`"Confirmed"`. | ~`+70` LOC across `tuning-rack.ts`, `BenchWorkspace.svelte` | `tuning-rack.ts`, `BenchWorkspace.svelte`, `bench.test.ts` (`workspaces.test.ts` signature unchanged) | Deleting the unused callback prop from `WorkspaceShell`/`BenchWorkspace` ahead of `#11` |

**Adopter seam:** `+page.svelte` passes no actuation callback and `skgStore` ingests no `PARAM_VALUE` triples today, so production `Diagnostics` always resolves `baselineSource: "domain-default"` and zero outbound WebSocket/HTTP command frames can fire. Test suites can seed `{ baseline, source: "vehicle-reported" }` via `DiagnosticsDraftStore` to prove provenance copy distinguishes sample defaults from future vehicle-reported parameters (`#43` verification plan), and `#11` will extend `TuningBaselineSource` with `PARAM_SET` lifecycle states instead of scraping UI strings.

## Risks / Trade-offs
- **Existing test assertions:** `bench.test.ts:219-226` currently asserts `applyBtn.click()` calls `onApply` once on a `"rover"` default baseline; under both `D2` Option A and Option B (which blocks `"domain-default"` actuation), that test updates to assert offline non-actuation on sample defaults (and under Option B, optionally tests the callback only on `"vehicle-reported"` fixtures), while `#40` round-trip tests (`bench.test.ts:1405`, `cop-workspace.e2e.ts:1472`) align with always-visible baseline/bounds formatting.
- **Panel density ahead of `#42`:** Adding per-control numeric inputs, bounds metadata, and a compact diff summary inside `.tuning-panel` (`minmax(320px, 1fr)`, `BenchWorkspace.svelte:775`) must use compact inline rows (`flex-wrap` / tabular numerals) so controls do not overflow horizontally at `1024×768` and `1440×900`.
