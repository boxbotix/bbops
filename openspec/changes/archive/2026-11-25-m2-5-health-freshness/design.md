## Goals / Non-Goals
- **Goals:** Prevent false `Nominal` claims on startup/empty/disconnected/stale states; align UI per-vehicle freshness with `#27` link-loss signals and `LinkTier` cadences; preserve retained faults as visibly last-known with age; represent partial `Telemetry` vs. `Fleet data` degradation accurately; surface explicit `ARMED`/`DISARMED` status consistently.
- **Non-Goals:** Altering `0xB1` fault rules (`evaluateActiveVehicleFault`), changing transport backoff (`ws-client.ts:14-16`), adding alert ack workflows, or wiring `M3.1` actuation (`#11`).

## Decisions

### D1: Per-vehicle observation freshness threshold & `WS #1` / `WS #2` signal arbitration
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (`LinkTier`-scaled state freshness + `skg` `observedAt` high-water + per-`sysid` `WS #1` `link_lost` latch)** — Keep `WS1_KINEMATICS_FRESH_MS = 1_000` for `20 Hz` pose selection; scale vehicle observation freshness by `LinkTier` (`4_000 ms` for `sitl-local`/`direct-bench`/`mesh-high-rate` = `3_000 ms` `#27` timeout + `1_000 ms` `1 Hz` SKG tick margin; `11_000 ms` for `mesh-supervisory`). High-water `observedAt` in `skg.svelte.ts` (`stateIngestedAtMs`/`stateIngestedLive`) and latch per-`sysid` `linkLost` + latest observation receipt in `telemetry.svelte.ts` (`link_lost` forces stale immediately; `link_restored` or newer SKG `observedAt` / `WS #1` frame clears it). | ~`+95` LOC across `skg.svelte.ts`, `telemetry.svelte.ts`, `view-model.ts` | Stores + `view-model.ts` + Vitest suites | Assuming flat `2.5 s` staleness on `LoRa 1Hz` (`0.2–1 Hz`) supervisory links |
| **Option B (Flat `2_500 ms` `SKG_VEHICLE_FRESH_MS` across all `LinkTier`s, timestamp-only without `WS #1` `link_lost` latch)** — Apply `2_500 ms` uniformly to `observedAt` without per-`sysid` `link_lost` state in `telemetry.svelte.ts`. | ~`+45` LOC in `skg.svelte.ts`, `view-model.ts` | `skg.svelte.ts`, `view-model.ts` | Stable `LIVE` status on `0.2–1 Hz` `mesh-supervisory` links (flaps stale between valid packets) and surviving 100-event ring eviction of `link_lost` |

**Adopter seam:** `evaluateVehicleFreshness(vehicle, { telemetryStore, skgStatus, nowMs })` in `hud/view-model.ts` becomes canonical for health/state freshness while `resolveLiveVehiclePose` remains canonical for `20 Hz` vs. SKG pose. Callers omitting `telemetryStore` fall back safely to SKG `observedAt` freshness.

| Option | Cost | Blast radius | Forecloses |

### D3: Stale/last-known UI treatment, `ARMED` / `DISARMED` consistency, & clock updates
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (`1 Hz` shell clock + explicit `LAST KNOWN (<age>)` & `ARMED`/`DISARMED` labels)** — Drive a single `1_000 ms` clock in `WorkspaceShell.svelte` (injectable `now?: () => number`, zero `20 Hz` thrash) so silent vehicles transition to stale and advance age (`4s ago`, `1m 12s ago`) even when `#29` suppresses silent SKG `put`s. **Adopter seam:** `WorkspaceShell` accepts optional `now?: () => number`; tests pass a controlled clock + fake timers while production uses `Date.now` on a `1_000 ms` interval cleaned up on unmount.

## Risks / Trade-offs
- **Producer vs. browser clock skew:** Following `skg.svelte.ts:823-863`, live post-`synced` `put`s measure elapsed time from local receipt (`now()`) whenever `observedAt` strictly advances, while initial/reconnected pre-`synced` snapshots check `nowMs - Date.parse(observedAt)` so cached snapshots from already-silent vehicles start stale immediately.
- **E2E selector migration:** `ui/e2e/cop-workspace.e2e.ts:259-270` currently matches `WS1: connected (3)` / `WS2: connected`; updating it alongside a new disconnected-startup browser assertion keeps full-stack coverage green.
