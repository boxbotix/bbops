## Goals / Non-Goals
- **Goals:** Preserve per-vehicle Diagnostics staged values, captured baselines, and staged counts across workspace and vehicle switches while keeping single-stage mounting and command guards intact; isolate per-vehicle `Revert Draft` and explain removed/non-commandable entities; preserve Analysis query text, tier, completed results, result provenance, and 2-hop inspection context across workspace switches; prevent out-of-order or navigation-spanning searches from overwriting newer queries or misattaching to another entity.
- **Non-Goals:** Reload/disk persistence, cross-device sync, undo history, `#43` parameter provenance copy redesign, or `#11` `PARAM_SET` actuation.

## Decisions

### D1: Shell-owned `DiagnosticsDraftStore` & non-commandable / removed entity draft lifecycle
| Option | Cost | Blast radius | Forecloses |
| --- | --- | --- | --- |
| **Option A (Retain dormant per-`entityId` draft across transient `poisoned` / `delete`; restore only on matching canonical `entityId` + `domain`)** — Add `createDiagnosticsDraftStore()` (`tuning-rack.ts`) owned by `+page.svelte` / `WorkspaceShell.svelte`, keyed strictly by canonical 6-part UXS vehicle ID (`parseVehicleEntityId(id) !== null`, `uxs.ts:115-129`) storing `{ entityId, domain, baseline, staged }`. Keep tuning inputs/`Apply` withheld whenever `selectedCommandableVehicle === null`, explain removed/generic/poisoned/external-contact status explicitly for `selectedEntityId`, surface a dormant-draft notice + `Revert Draft` button if that `UXS #sysid` holds staged changes while poisoned/absent, and reset on domain mismatch. | ~`+90` LOC across `tuning-rack.ts`, `BenchWorkspace.svelte`, `WorkspaceShell.svelte`, `+page.svelte` | Bench store/component, shell props, `bench.test.ts`, `workspaces.test.ts`, E2E | Automatic silent wipe of operator tuning work on a transient decode/disconnect blip |
| **Option B (Eagerly purge a vehicle's saved draft immediately on `skgStore` `poisoned` or `delete`)** — Same shell-owned `DiagnosticsDraftStore` and canonical `parseVehicleEntityId` isolation, plus a shell `$effect` that deletes `drafts.get(id)` whenever `skgStore` marks `id` `poisoned` or removes it from `entities` after `synced`, displaying a notice that prior local staging was cleared. | ~`+80` LOC across same files | Same files | Recovering in-progress tuning edits after a single corrupt frame or brief entity re-ingest |

**Adopter seam:** `WorkspaceShell` creates a default `DiagnosticsDraftStore` when omitted in unit tests, and `BenchWorkspace` reads/mutates drafts only for validated `parseVehicleEntityId` keys without calling `onApplyTuning` on mount/unmount/selection changes. Callers doing nothing get session continuity automatically; `#43` can attach parameter-source provenance directly onto the per-vehicle `{ baseline, staged }` record.

### D2: In-flight `Analysis` search lifecycle across workspace switches

### D3: `Analysis` inspection context & earlier-selection provenance when global selection changes
| Option | Cost | Blast radius | Forecloses |

**Adopter seam:** Result provenance (`submittedQuery`, `submittedTier`, `mode`, `scopeEntityId`) is always captured at submission time rather than read from live `queryText` / `activeTier` / `selectedEntityId`, so editing the search box or switching vehicles never mislabels existing hits; callers doing nothing inherit sanitized 6-part entity ID scoping.

## Risks / Trade-offs
- **Memory bound:** Session drafts cover at most `1..=254` canonical UXS vehicles (`6` numeric keys each) and `AnalysisSessionStore` retains only the latest completed result set + single 2-hop `pathResults` array, adding negligible memory with zero `20 Hz` reactivity coupling.
- **Test contract alignment:** Under `D2` Option A, `workspaces.test.ts:758` shifts from asserting `AbortSignal.aborted` on tab switch to asserting zero cross-workspace selection/hash mutation on background settlement plus `AbortSignal.aborted` on explicit cancel, superseding search, and shell unmount.
